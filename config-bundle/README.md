## TLS certificate setup notes (Task E)

Done once on Laptop 2 (Bhavay) with `./scripts/make-certs.sh` (OpenSSL 3):

1. **Root CA**: RSA 2048, self-signed, `basicConstraints=critical,CA:TRUE`,
   `keyUsage=keyCertSign,cRLSign`, valid 825 days → `certs/ca.crt` + `certs/ca.key`.
2. **Server certificate**: RSA 2048 key + CSR for `CN=app.team67.test`, signed by the CA with
   `subjectAltName = DNS:app.team67.test, DNS:api.team67.test`, `extendedKeyUsage=serverAuth`,
   `keyUsage=digitalSignature,keyEncipherment`, valid 397 days (macOS rejects longer) →
   `certs/server.crt` + `certs/server.key`.
3. Verified with `openssl verify -CAfile ca.crt server.crt` → `server.crt: OK`.
4. **Distribution**: `ca.crt` shared to the other laptops over the LAN and its SHA-256 fingerprint
   compared by hand on all three (`78:AE:96:14:…:6A:C9`). `ca.key` never left Laptop 2.
5. **Trust**: each client ran `./scripts/trust-ca.sh` →
   `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ca.crt`.
6. nginx loads `server.crt`/`server.key`, `ssl_protocols TLSv1.2 TLSv1.3`, `http2 on`.
7. Result: `curl https://app.team67.test` → `SSL certificate verify ok`, no `-k` anywhere.
